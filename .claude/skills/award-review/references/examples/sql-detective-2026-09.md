# 審查案例：SQL 偵探：潮港市檔案（2026-09-30）

**專案背景**：純靜態站（HTML + Tailwind v4 + vanilla JS + GSAP），互動式 SQL 教學遊戲，深色霓虹港都主題，已有大量插畫素材。驗證工具：Playwright MCP。

用來校準尺度：拿到新專案時先讀這份，知道「差距」要寫到多具體、「計劃」要切到多細。技術細節（Tailwind class、CSP）是這個專案的限制，換專案時看做法背後的判斷，不照抄手法。

## 十秒測試結果

首屏三個詞：乾淨、現代、像 SaaS。辨識度不及格——霓虹港都的插畫很好，但版型是左文右圖加兩顆按鈕。

## 不要動的強項

- 世界觀一致：霓虹港都色票、拍立得證據板、劇情舞台、開場 MV、Web Audio 聲景貫穿三頁。證據板是全站最有得獎相的畫面。
- 內容量與功能：七章 85 題、真實 sql.js 執行、中文錯誤翻譯、三段提示、徽章與證書。Webby 的 Content / Functionality 幾乎滿分。
- 工程品質：CSP、a11y、reduced-motion 全站處理、快取版本號流程。

## 計劃與實際取捨

**P0（當天完成）**：自架字型切片、標題 nowrap 與 object-position、統一文案、SVG 圖示、第 0 章寬卡消孤卡、View Transitions。

**P1（首頁重做）**：
- 簽名時刻押在 hero：打字機打出 `SELECT truth FROM chaogang_city;`，結果回來時插畫亮起、標題進場；同一張插畫的亮版以 mask 跟隨游標露出（手電筒）。沒有拆圖層做真視差，因為沒有分層素材，改用「同圖兩層＋mask」達到類似效果。
- 章節區從卡片格改為「卷宗」：左側軸線、明體大章號、圖文交錯、印章狀態。軸線用章號上下兩段偽元素接成，避免用底色遮線（body 有固定漸層會露色塊）。
- 展示字只加 Noto Serif TC，用在 h1/h2/章號/規格數字；內文不動。
- 八張語法小卡改為卷宗封面規格表（dl），移除玩法區與規格區的逐段進場。
- 否決：自訂游標（a11y 風險大於收益）、橫向捲動章節（手機體驗差）。

**P2（遊戲頁沉浸化）**：查詢區終端機語彙（狀態燈、掃描光束、逐列列印）、徽章解鎖滿版儀式、獨立可分享的結案證書頁與專屬 OG 圖。

## 實作後對照

- 首屏三個詞變成：黑色電影、卷宗、港口。遮掉 logo 仍認得出。
- 手電筒與打字序列只在 hover 裝置與未要求減少動態時啟用，手機與 reduced-motion 直接顯示完整畫面。
- 剩餘差距：手機 hero 仍是橫圖裁切，徹底解法要另出直式素材；making-of 頁與預覽影片尚未做（P3）。
